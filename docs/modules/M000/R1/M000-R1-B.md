# M000-R1-B – Git, environment, and security

Package B extends the stable operator framework with trusted, read-only contracts. It does not execute Git or any other native program and does not implement a process manager.

## Implemented files

- `scripts/operator/modules/Operator.Git.psm1` owns the trusted repository policy, fixed Git inspection plan, captured-output conversion, repository snapshot validation, and working-tree fingerprints.
- `scripts/operator/modules/Operator.Environment.psm1` owns read-only tool requirements and detection for Windows PowerShell, Git, Node, npm, Docker, project-local Supabase CLI, and Pester.
- `scripts/operator/modules/Operator.Security.psm1` owns path policy, secret hints, local/remote connection protection, and exact Git target/argument allowlisting.
- `scripts/operator/modules/Operator.Reporting.psm1` adds validated atomic writers for `environment.json`, `repository-snapshot.json`, and `working-tree-fingerprint.json`, plus a redacted invocation report, without changing result schema 1.
- `scripts/operator/portal-operator.ps1` imports the package-B modules by paths derived from `$PSScriptRoot`; it still returns `blocked`/`20` for valid local stages and deployment stages.
- `docs/project/operator-framework-contracts-v1.md` records the cross-package contracts.

## Git policy and snapshot

The code-owned M000 policy binds branch `infra/m000-r1`, no upstream, and exact ordinal remote mappings: `origin` to `https://github.com/Plaerrdeifl/portal.git` and `v4dev` to `https://github.com/Plaerrdeifl/portal-v4-dev.git`. A trusted caller may additionally bind the full HEAD SHA. Snapshot validation returns fixed structured violations for malformed external data instead of leaking values or throwing; only malformed trusted policy code is an internal error. Snapshot reporting accepts only fully typed, closed objects and the two complete canonical HTTPS mappings. String-to-integer, string-to-Boolean, array, object, and null coercions are forbidden. URL aliases, normalization, query, fragment, UserInfo, SSH, file, relative, missing, and extra remotes are rejected before writing, and invalid input cannot create or replace a report.

The fixed inspection plan contains only repository root, full HEAD, current branch, upstream, remote URL configuration, and porcelain working-tree status targets. Manifest data cannot change targets or arguments. Package B only converts already captured output into a closed snapshot with schema version, root, HEAD, branch, nullable upstream, sorted remotes, working-tree state, and UTC capture time.

## Path policy

Changes are allowed only under `scripts/operator/`, `docs/project/`, and `docs/modules/M000/R1/`. Everything else is denied, including `.gitignore`, `.git`, application code, dependencies, CI, tests, and Supabase migrations/functions. The repository root must exist as a directory and neither it nor any absolute parent segment may be a reparse point. Resolution rejects empty, absolute, UNC, device, drive-qualified, ADS, control-character, current/parent-segment, traversing, root-escaping, and reparse-point paths. Windows segments with trailing spaces or dots, reserved device names (also with extensions), 8.3 short names, case aliases, and other filesystem normalization aliases are blocked. After `GetFullPath`, the canonical target is derived segment by segment from the controlled root; its slash-normalized repository-relative form must equal the checked input ordinally. Containment is never decided by a textual prefix, and no rejected traversal is read outside the repository.

## Working-tree fingerprint

Fingerprint schema 1 uses SHA-256 over canonical UTF-8 without BOM. Every dynamic field is encoded independently as its UTF-8 byte length plus Base64, so tabs, CR/LF, Unicode, and empty values cannot collide with record boundaries. Canonical data includes full HEAD, branch, upstream, ordinally sorted remote mappings, and ordinally sorted relative status paths with status code, original rename/copy path, item kind, and current file SHA-256. Missing/deleted files, directories, and final reparse points have distinct markers. A final reparse point is recorded without following or hashing its target; a parent reparse point is blocked. Repository root, timestamps, file contents, and diffs are excluded, and reads cannot leave the repository root. Before comparison or reporting, both fingerprint objects must be closed PSCustomObjects with integer schema version 1, exact `SHA256`, lowercase 64-character fingerprint, lowercase 40-character HEAD, non-negative integer entry count, and exact UTC timestamp. Invalid objects always produce a fixed non-match or fixed writer error; two equally invalid objects never match.

## Secret hints

The scanner examines only regular non-reparse files within the root, up to 1,048,576 bytes, using a bounded stream read of at most 1,048,577 bytes and strict UTF-8 or BOM-declared UTF-16 decoding. Oversize, binary, and invalid text are skipped safely without loading an unbounded file. Rules cover private keys, JWT-like values, Supabase and GitHub token forms, URL credentials, password connection strings, and non-placeholder assignments to sensitive names. Empty values, environment references, documented placeholders, `CHANGEME`, examples, and clearly marked dummy values are excluded. Findings contain only rule ID, relative path, line number, severity, and a fixed description—never the matching value or source line.

## Environment contract

Tool detection uses PowerShell runtime metadata, `Get-Command`, `Get-Module -ListAvailable`, file metadata, fixed project-local candidates, and controlled package metadata reads. No tool is run, installed, or imported. Project-local Supabase candidates and their package metadata are accepted only through fully normalized, segment-by-segment reparse-free paths; a global Supabase CLI is neither required nor considered. Node requires `>=24.18.0 <25`; Windows PowerShell requires 5.1. Versions that cannot be obtained without execution stay null with `unknown` status. Pester versions are collected read-only and deterministically sorted. Environment snapshots are closed and centrally validated for timestamp, exact tool identity, scalar field types, trusted requirements, availability, control-character-free paths/sources, and version-status consistency before reporting. Schema version is accepted only as an actual integer with value 1; strings, null, arrays, objects, Booleans, unknown properties, and all other malformed external structures return fixed structured violations without throwing or leaking property names. Unavailable tools cannot carry a resolved path or detected version. Malformed trusted requirements remain an internal operator error.

## Reporting redaction

Snapshot and fingerprint writers validate the complete closed type contract before serialization and before any atomic replacement. Reported strings reject CR, LF, and null characters. `invocation.json` writes only one of the nine exact registered stages or the fixed value `INVALID`; it always records `manifestPath` as `<redacted>` and never stores the supplied path, filename, invalid stage text, or related exception data. Its invocation timestamp remains canonical UTC.

## Local/remote protection

Local mode blocks DEV project ref `tpieykhhawszlzsoflnl`, PROD project ref `wplescvhlgctynkfwvrj`, their Supabase and pooler hosts, matching `--project-ref` arguments, linked refs, non-local PostgreSQL targets, remote Supabase URLs, and non-local hosts in classical `Host`, `Server`, `Data Source`, `Address`, `Addr`, or `Network Address` connection strings. Connection metadata must be a closed object with a case-sensitive source ID matching `^[a-z0-9][a-z0-9._-]{0,63}$`; malformed IDs are rejected without echoing them. Environment findings report only the variable name. Link-state inspection is limited to `supabase/.temp/project-ref` and `.supabase/project-ref`; missing files are accepted. Localhost, `127.0.0.1`, `::1`, and `[::1]` remain local.

Only exact registered Git target-and-argument pairs are accepted. Fetch, pull, push, clone, `ls-remote`, remote/submodule updates, commit, merge, rebase, reset, clean, checkout, switch, write forms of branch/tag/config/worktree, hooks, uploads, and remote APIs have no registration and are blocked.

## Package boundary and validation

Package B has no process engine, native process execution, stdout/stderr logging, timeouts, health checks, cleanup, Pester test files, M000 manifest, full SelfTest, LocalVerify, LocalFreeze, deployment, success outcome, or success marker. Real repository and fingerprint reports are not emitted until a later trusted process manager has captured real Git data. The process manager belongs exclusively to package C; complete checks follow in C/D.

Validation covers Windows PowerShell 5.1 parsing, static prohibited-pattern checks, Git policy boundaries, path traversal and reparse protection, deterministic fingerprints, secret redaction, local/remote detection, environment detection, package-A regression behavior, and final Git scope checks. There are no known package-B implementation blockers.
